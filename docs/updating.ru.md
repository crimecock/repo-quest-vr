# Когда R.E.P.O. обновляется

[English](updating.md) · **Русский**

Обновление игры может сломать порт четырьмя способами, как это сделала 0.5.0:

1. **Изменился код игры**: патчи RepoXR не находят, что патчить, или транспайлер встаёт не туда.
2. **Игра вызывает новые API Steam**, которых нет в SteamShim (клиенте Steam в шлеме).
3. **Изменились пакеты Unity или движок**: новые версии пакетов, новый каталог Addressables, новая Unity.
4. **AssetRipper экспортирует что-то иначе** (0.5.0: без PlayerSettings, WAV без размеров).

Первые три видны за минуты без Unity — командой `QuestBuilder.Cli check`. Четвёртое — только через экспорт и сборку.

## Обновление на новую сборку форка

Новый набор (например, 1.0.7-qc24 → qc27) чаще всего меняет только код: соберите заново с
`CODE_ONLY=1 scripts/build-mac.sh` (Windows: `scripts/build-windows.ps1 -CodeOnly`). Unity берёт данные игры,
упакованные прошлой полной сборкой, и пересобирает только код: около 6 минут вместо 30–35. Когда нужна полная сборка
(поменялись ассеты, экспорт или Python-скрипты), это написано в примечаниях к выпуску. Новый APK ставится поверх
старого: сохранения, настройки и вход в Steam остаются ([install.ru.md](install.ru.md)).

## Игрокам

Руками ничего делать не нужно. Если в Steam версия игры, с которой набор не проверялся, `scripts/build-mac.sh` и
`scripts/build-windows.ps1` сначала сами запускают проверку:

- **без ошибок** — сборка продолжается (новая версия скорее всего работает);
- **с ошибками** — скрипт останавливается и показывает `work/check-report.md`. Дождитесь нового релиза форка (или
  откройте issue с отчётом). `FORCE=1` (macOS) или `-Force` (Windows) — собрать всё равно.

Чтобы сохранить рабочую версию, собирайте из копии игры, которая сама не обновляется: скрипт для macOS скачивает свою
копию через `steamcmd`, она обновляется только если её удалить; на Windows передайте `-Game` с копией папки игры или
поставьте в Steam обновление игры только при запуске.

## Тем, кто поддерживает форк

### 1. Проверка

```bash
dotnet build -c Release builder/QuestBuilder.Cli
builder/QuestBuilder.Cli/bin/Release/net8.0/QuestBuilder.Cli check --kit <распакованный набор> --game <папка игры> --workspace <рабочая папка>
```

Проверка встраивает патчи в новый код игры (шаг bake сборки после неё уже готов) и пишет `check-report.md`:

| Раздел | Что значит | Где исправлять |
|---|---|---|
| `bake` | Классы патчей, которые упали (метод или поле исчезли, неоднозначная перегрузка) | новый патч RepoXR (2) |
| `il` | Невалидный IL во встроенном методе (IL2CPP отказал бы через 40 минут сборки) | транспайлер, который его менял (2) |
| `types` | Значение одного класса кладётся туда, где игра хранит другой (clang не скомпилирует C++ от IL2CPP) | транспайлер (2) |
| `patches` | Пропатченный метод не изменился (патч ничего не нашёл) или изменился только в самом конце (транспайлер потерял якорь) | патч (2) |
| `anchors` | Поиск транспайлера ничего не нашёл (предупреждение). Без `ThrowIfInvalid` правки после него попадают в конец метода или в середину чего-то другого: на 0.5.0 так выключился захват. Циклы, у которых кончились совпадения, не считаются | транспайлер (2); если искомый код необязательный, проверяйте его через `IsValid` |
| `refs` | Вызов между игрой, RepoXR, RepoXR.Standalone и SteamShim больше не находит цель | SteamShim (`tools/SteamShim/Api.cs`) для API Steam, `tools/RepoXR.Standalone` для его замен, RepoXR (2) |
| `unity` | Новая версия Unity | `builder/kit.json`, `scripts/lib/paths.py`, `scripts/make_lamp_shaders.py`, версии пакетов, Unity-инструменты (см. [repo-0.5.0.ru.md](repo-0.5.0.ru.md)) |
| `addressables` | Новая версия Addressables или каталог не читается | `scripts/addressables_catalog.py`, `scripts/package_swap.py` |
| `packages` | В DLL пакета другие типы — новая версия пакета | подобрать и закрепить в `scripts/package_swap.py` (и `ProjectStep` для встраиваемых пакетов) |
| `managed` | Новые или пропавшие DLL | новые пакеты или библиотеки; обычно ничего, иногда пакет для замены |

### 2. Исправить патчи RepoXR

Один патч на версию игры, поверх существующих:

```bash
git submodule update --init external/RepoXR
scripts/repoxr-patch.sh start          # work/repoxr-edit: RepoXR + все патчи из patches/repoxr, как git-репозиторий
# правьте work/repoxr-edit/Source, пока проверка не станет чистой
scripts/repoxr-patch.sh save repo-0.5.1   # -> patches/repoxr/0010-repo-0.5.1.patch
```

Впишите новый патч в заголовок `scripts/prepare-repoxr.sh`. Соберите RepoXR против нового кода игры ([build-repoxr.ru.md](build-repoxr.ru.md)), затем
RepoXR.Standalone и SteamShim, и прогоняйте проверку с этими DLL в наборе, пока ошибок не останется.

### 3. Собрать и проверить

Соберите APK (`scripts/build-mac.sh` или `scripts/build-windows.ps1`) и сыграйте в шлеме: меню, одиночная игра,
уровень, магазин, вход к другу на ПК.

Пока чините код (патчи RepoXR, RepoXR.Standalone, SteamShim, встраиватель, скрипты `unity-tools`), после одной полной
сборки собирайте только код: `CODE_ONLY=1 scripts/build-mac.sh` или `-CodeOnly`. Unity берёт упакованные данные игры из
прошлого APK и пересобирает только код, IL2CPP и Gradle: около 6 минут вместо 35. Всё, что меняет ассеты (экспорт,
Python-скрипты, шейдеры, бандл ассетов RepoXR), требует полной сборки. В шлеме пишите лог во время запуска игры:
`adb logcat -c && adb logcat -s Unity AndroidRuntime CRASH > log.txt`
([playing.ru.md](playing.ru.md#если-что-то-не-так)); строки самого RepoXR начинаются с `[RepoXR]`.

### 4. Выпустить

Добавьте раздел `## <версия>` в оба журнала — [CHANGELOG.md](../CHANGELOG.md) и [CHANGELOG.ru.md](../CHANGELOG.ru.md) — (из них берётся описание релиза на двух языках), закоммитьте и запустите:

```bash
GITHUB_TOKEN=... scripts/release-fork.sh 1.0.7-qc3 --dlls <папка с тремя DLL> \
    --game <проверенная папка игры> --game-name v0.5.1
```

Скрипт соберёт набор (текущий набор со скриптами, Unity-инструментами из этого checkout и новыми DLL), запишет версию
игры как проверенную (`builder/kit.json`) и как новую базу для проверки (`scripts/game_fingerprints.json`), обновит
версию и контрольную сумму в обоих скриптах сборки, поставит тег, зальёт набор в ветку `kit` и создаст релиз на GitHub.
`--dry-run` делает всё, кроме коммита и отправки; `--prerelease` помечает непроверенную сборку.
